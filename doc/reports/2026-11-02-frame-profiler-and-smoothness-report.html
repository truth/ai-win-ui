1 问题现象与渲染链路剖析

在执行 .\scripts\run_layout_demo.ps1 -Layout "modern_components_v2" -Renderer "skia" 时，拖拽调整窗口尺寸与点击圆角 <Switch> 开关存在肉眼可见的卡顿与滞后。通过梳理宿主消息循环与渲染器管线，定位出优化前单次交互的 6 步串行链路：

1. WM_LBUTTONDOWN / WM_SIZE
→
2. 无条件整页 UpdateLayout (55.3 ms)
→
3. InvalidateRect 整窗脏标记
→
4. 等待低优先级 WM_PAINT
→
5. Debug 软光栅全量重绘 (135.9 ms)
→
6. BitBlt 上屏 (0.6 ms)

3 五项靶向优化技术细节

序号 优化模块 修改文件 根因与修复方案
#1 启动脚本默认 Release 构建 scripts/run_layout_demo.ps1 原脚本固定启动 Debug\ai_win_ui.exe，链接了未优化的 Debug-x64/skia.lib（CPU 软光栅慢 28 倍）。现新增 -Configuration Auto|Release|Debug，交互式运行默认采用 Release，CI -NoLaunch 自动保持 Debug 兼容。
#2 Skia 字体、排版与 SVG 路径三级缓存 src/skia_font_shared.h
src/skia_text_layout.cpp
src/renderer_skia.cpp		 原实现每次调用 CreateDefaultTypeface 均通过 DirectWrite 重新创建 SkTypeface，导致 Skia 内部字形缓存 SkStrikeCache 失效。现对 CreateDefaultTypeface、CreateSkiaTextLayout（4096 项）及 DrawSvgPath 增加哈希缓存。
#3 按需触发 UpdateLayout() src/ui_host.cpp
src/ui_containers.h
src/ui_widgets.h		 移除 UiHost::OnMouseDown 中无条件执行的整页 UpdateLayout()，改为仅在改变组件尺寸的 Expander（折叠/展开）和 AlertBanner（关闭隐藏）中调用 m_context->requestLayout()。
#4 Switch 与 SegmentedControl 140ms 缓动 src/ui_widgets.h 在 16ms OnTimer 帧循环中推进动画进度：Switch 使用 Smoothstep ($3t^2 - 2t^3$) 插值圆钮水平位置与轨道颜色；SegmentedControl 平滑滑动选中态白色胶囊背景。
#5 DIB 64px 步进容量复用与同步重绘 src/renderer_skia.cpp
src/ui_host.cpp		 SkiaRenderer 按 64px 步进对齐分配 GDI DIB 容量（m_dibCapWidth × m_dibCapHeight），拖拽缩放时复用已有位图内存并以 rowBytes = m_dibCapWidth * 4 重新包装 SkSurface；UiHost::OnResize 调用 RedrawWindow(..., RDW_INVALIDATE | RDW_UPDATENOW) 同步上屏。
