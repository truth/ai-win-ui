5客观结论与工程优化建议

  • UI 线程 Apply 几乎零成本 (`0.01~0.07 ms`)：采用整型二进制 `MutationBatch` 与视觉快路径后，即使每 16ms 批量修改 100 个数值节点，UI 线程 `apply_ms` 仅 `0.038~0.040 ms` 且 `layoutTotal = 0`。
  • 纯原生手势/缩放在 React 模式下 ZERO JS 税：60Hz 图表十字光标跟随 (`~6.0–6.6 ms`) 与 60Hz 窗口缩放 (`~11.5–12.2 ms`) 由 C++ 独立完成，JS 线程占用为 `0 ms`。
  • 乐观 UI 打字仅 ~1.1 ms（0ms 心理阻尼）：连续 `WM_CHAR` 击键立即渲染耗时 `1.08–1.22 ms`（XML 为 `0.99–1.14 ms`）；React 后台异步状态校验在 `2.5–3.2 ms` 内静默完成并通过 `eventSeq` 过滤过期回显。
  • React JSX 额外开销主要在纯 JS Diff（约 `+2.8 ~ +5.3 ms`）：262 节点金融终端整树 Reconcile 在 QuickJS 下耗时 `3.5~9.1 ms`，总交互响应保持在 `9.1~12.6 ms`（低于一帧 16.6ms 预算）。
  • 高频 60Hz 定时精准度优于 Win32 `SetTimer`：React 独立 Worker 线程配合 `PostMessage` 稳跑 **`59.44–59.72 FPS`**，而共享 UI 线程 `SetTimer(16ms)` 受 Windows 15.6ms 量子合并限制掉到 `~42.0 FPS`。
  • 内存与冷启动代价极低：内嵌 QuickJS-ng + 自研 TS 运行时仅新增 **`+1.8 ~ +2.0 MB`** 常驻内存；冷启动首个内容帧耗时 `45.5 ms`（Skia），与 XML (`47.0 ms`) 持平。
  • 下一步可挖掘红利：在 TS 运行时引入 `React.memo` 剪枝可把 262 节点主题/周期切换时的 JS Diff 从 `4~9 ms` 压至 `< 1.5 ms`；同时消除图表 500ms Tick 伴随的次级 `invalidate` 帧，可使空转绘制减半。
